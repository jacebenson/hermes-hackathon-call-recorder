# Legacy v1 simplification notes

Historical review of the backend/old UI, not the v2 client-local release. See the root README for current behavior.

Leave the capture algorithms alone. Linux/PipeWire and Windows/WASAPI have end-to-end verification; this review does not repeat it. Their session handling, graceful shutdown, upload chunking and silence padding solve real failures. A rewrite would buy little. The worthwhile changes are unused paths and small duplications, ranked below by payoff. No code changed. Line numbers refer to `cba03ef`.

1. **Remove the unused live HTTP viewer.** `scripts/live.py:17,38,136-160` starts an unauthenticated server on `0.0.0.0:8799`. The desktop already gets transcripts through `dashboard/plugin_api.py:346-351`; no repository caller uses the viewer. Delete the handler, server and `LIVE_PORT` knob, leaving an explicit wait to keep the daemon threads alive. Safe for the shipped UI and removes an extra network service. Risk: someone may use the standalone viewer outside this repo. Until removed, the README must disclose it; the old claim that nothing listens was false for live transcription.

2. **Merge the two chunked Windows upload loops.** `capture_windows_wasapi.py:38-59,115-127` duplicates directory creation, staging, 1500-character chunks, decoding and existence checks. Extract one byte uploader; let `install` pass script bytes and `_write_text` pass UTF-8-with-BOM bytes. Same commands and payloads make this low risk. Preserve BOM handling, chunk size, cleanup and each caller's result keys. Do not replace it with one large command, which Windows truncates.

3. **Drop the unused transcription duration argument and probe.** `transcribe.py:50-60` never uses `duration`, but `dashboard/plugin_api.py:383` calls `rec.duration(path)` to supply it. Remove the argument and that `ffprobe` round trip; update positional test calls in `tests/test_transcribe.py:38-68`. Safe because duration affects neither transcription nor its result. Risk: an external Python caller may rely on the signature. Keep `Recorder.duration`, which the recording list uses.

4. **Delete the second archive-transcription entry point.** `recorder.py:581-593` has no repository caller. The dashboard uses `transcribe.py:27-60`, which also propagates the model and CUDA environment. Delete `Recorder.transcribe` instead of trying to keep two implementations aligned. Safe for in-repo calls; risk is an undocumented external caller. Keep the active entry point's error and segment-count contract.

5. **Share Windows shell and file-size helpers.** Quoting is identical at `capture_windows.py:43-44` and `capture_windows_wasapi.py:25-26`. The same size command and parser appear at `capture_windows.py:130-136,164-168` and `capture_windows_wasapi.py:225-230,257-261`. Merge these into small Windows-only helpers, preserving zero on missing or invalid output. Low risk with command-shape tests. Do not merge the stop loops or duration parsers: DirectShow tracks a PID, WASAPI waits for mux output, and their output handling differs.

6. **Remove unused scaffolding, not supported backends.** No repository callers use `platforms.py:70-77`'s AVFoundation parser, or `recorder.py:109-111,487-489,596-604`'s `human_clock`, `stop_live` and `from_settings`. Delete after checking external consumers. Also delete the unused `subprocess` import at `capture_windows_wasapi.py:249`, unused locals `now` and `level` at `recorder.py:405,414`, and the ignored `fresh` parameter at `recorder.py:379`. Safe internally; external imports or keyword callers are the risk. Keep DirectShow: `Recorder.start/stop/status` still dispatch to it.

7. **Split the recording row out of the pane.** `desktop/plugin.js:251-569` mixes queries, controls, live lines and recording rows. Extract only the row at `461-561`, passing existing state and handlers. This removes the deepest nesting without redesigning polling or actions. Risk: losing the two-click delete confirmation or its timeout; preserve those interactions. Leave the SDK's `jsx`/`jsxs` form alone.

8. **Retire or label the standalone WASAPI probe.** Nothing in the repo invokes `scripts/wasapi_probe.py:1-51`; the shipped installer copies only `wasapi_capture.py`. Delete it if the author no longer uses it for manual diagnosis. Otherwise label it diagnostic-only and remove the unused `with_mic` parameter at line 24. Risk: losing a useful Windows smoke-test tool. Do not merge its blocking capture with the production callback path just to share device selection.

9. **Correct stale explanations before adding abstractions.** `platforms.py:3-7` still says Windows needs a driver; `capture_windows.py:3` cites a README platform matrix that does not exist. `recorder.py:525-530` says helpers are installed once, while dashboard detection overwrites them at `dashboard/plugin_api.py:217-224`. Update those comments to match WASAPI and the five-minute detection cache. No runtime risk. Keep the advanced settings: the settings loader consumes them, and repository inspection cannot show that nobody uses them.

## Boundaries worth keeping

Do not consolidate platform launches, archive/live Whisper settings or lazy SSH discovery for appearance alone. `recorder.py:765-810` repeats source selection, but the live path deliberately stops probing early. `scripts/live.py:53-70` repeats Linux source parsing because it runs remotely without the plugin package. Sharing either needs more deployment or behavior tests than the likely savings justify. `scripts/archive.py:39-81` and `scripts/wasapi_capture.py:103-170` are long but describe sequential workflows; splitting them now would mostly move code.

Two existing behavior gaps need separate fixes, not cleanup: pane Stop and watcher auto-stop do not invoke archive transcription, unlike composer Stop; and composer notifications treat a resolved transcription response as success without checking `ok`. The README now describes composer-stop transcription rather than promising it for every stop. Auto-start is also off by default in the dashboard and its tests, contrary to the old README. These are source findings, not new end-to-end reproductions.
